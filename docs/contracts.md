# V1 contract operations

## Wiring a pool

1. Upload the release WASMs. Deploy the stateless `deployment-factory` with an empty constructor. Select a signing admin and four distinct 32-byte salts. Each protocol address derives from the admin and its salt. Use those predicted addresses to wire the four instances.
2. Call the factory's `deploy(admin, salt, wasm_hash, config)` once per protocol contract. Pass the initializer arguments **after** the admin in `config`, in the order below. The factory supplies the admin to both the constructor and initializer. Both calls execute in one transaction. For direct deployment, supply the intended admin to the constructor and have that same identity authorize initialization.
3. Initialize the oracle with the administrator and a positive freshness window in seconds. Authorize price publishers. For a signed RedStone feed, configure signers and quorum, then map the collateral token address to its feed symbol.
4. Initialize the vault with the admin, pool, oracle and engine addresses. Initialize the pool with the admin, vault, oracle, borrow token and annual rate in basis points. The borrow token must expose seven decimals and represent one unit of the quote currency. Verify the network, issuer and asset identifier separately.
5. Initialize the engine with the admin, vault, pool and oracle. Check all four instances' configuration before supplying liquidity. Coordinate version changes across contracts. The pool uses the vault's `health_factor_for_debt` entry point.
6. Publish a fresh price and call `add_supported_asset(asset, config)` with the token decimals, oracle price decimals, maximum LTV and liquidation threshold. The vault validates the token decimals against the token contract. The operator supplies the feed precision. Risk metadata is locked while an asset backs an open position.

## Valuation and settlement

One quote unit is 10,000,000 base units. The vault and engine multiply the raw token amount by the raw price with a wide intermediate, apply their combined decimal scale, and round down once. For a mixed position, the lowest origination LTV applies to the total value when borrowing. The lowest liquidation threshold applies when computing health. Default settings are 70% and 80% respectively. A health factor of 10,000 basis points is the liquidation boundary. Debt-free users may withdraw without a current price after the pool confirms zero debt.

The pool charges fixed linear APR on principal. Each accrual carries fractional base units forward. Legacy debts default to zero carried fraction. Repayment pays interest first, caps the debit at outstanding debt and rejects a positive remainder below one quote unit. Closing a debt clears its fractional remainder. Paid interest increases the value of outstanding liquidity-provider shares. Suppliers at settlement time participate pro rata. A new deposit buys shares at the current price. Deposit conversion rounds down and partial withdrawal burns shares rounded up. A deposit that would mint zero shares fails. Call `get_user_supply` for a redeemable asset balance, then `withdraw_liquidity` to collect it subject to available cash. Accrued but unpaid interest does not increase a supplier's balance. Legacy supply balances begin at one share per base unit. Direct token donations do not change the share price.

The vault evaluates a multi-asset seizure against the position before the first transfer. The configured engine submits the basket and both dependency addresses in one call. The liquidation solver targets a health factor of 11,000 basis points, normally up to 50% of debt. It permits full settlement when the capped solution leaves dust or insufficient health. A caller may request a smaller repayment, so the target is not guaranteed. The liquidator signs the engine call, the nested pool repayment and the token transfer to the pool. Seizure uses an 8% bonus rounded up. If collateral cannot cover the entire debt plus bonus, the quote caps repayment at the amount it can cover and preserves at least the pool's minimum residual debt. The borrower still owes the remainder. A position too small for any permitted partial payment requires borrower or third-party repayment. Unpaid principal reduces the cash lenders can redeem. If rounding to an indivisible token would exceed the quoted seizure by a whole quote base unit, the engine rejects the amount. Simulate settlement to select a representable amount for that asset. A failed settlement rolls back token and position changes.

## Operations and recovery

- Borrowing requires both an active pool and permission from its configured vault. Switching the vault to another pool requires the old pool to confirm zero outstanding principal. A pool with outstanding principal also rejects a vault change. A failure to read debt or health propagates to liquidation eligibility callers.
- Manual price writes apply to unmapped assets. Mapped assets accept signed feed writes and reject observations ahead of ledger time.
- For suspect prices, pause pool borrowing and vault withdrawals and liquidations. Pause oracle writes while rotating an affected publisher. An oracle write pause allows reads of previously published prices until expiry. Repayment may stay available independently.
- To resume, check feed identity, units and freshness through `get_price_or_fail`, verify vault and pool addresses, and simulate a valuation and settlement. Unpause the affected operations individually.
- Track expiry ledgers for contract code, instances and persistent entries, including positions, indexes, debt, fractional interest, supplies, prices and config. Budget extensions before expiry and restore archived entries before resuming operations. TTL maintenance is an operator responsibility.
- Read positions with `get_positions_page(offset, limit)`. The maximum page size is 64. Offset pagination reflects the current active index. Use a consistent ledger snapshot or reconcile changes when scanning across ledgers. Each user has a separate slot and reverse lookup. Closing a position moves the final user into the vacated slot. The older full-list getters assemble the whole index and can exceed the read budget on large deployments.
- Token issuer freezes and clawbacks can impair custody. Confirm issuer policy and reconcile vault token balances against recorded collateral before resuming a restricted asset. The protocol has no automatic shortfall compensation.

Run `make check` locally. For settlement against compiled release artifacts, run `make test-wasm`.

## Vault upgrades and index migration

Version 3 changes the listing and upgrade interfaces. Regenerate clients from the release WASMs and coordinate the vault, pool and engine versions. Legacy pools without the outstanding-principal query cannot satisfy the vault's rotation guard. A live deployment with such a pool needs a separately verified migration plan.

For upgrades initiated by version 3, authorize `upgrade(wasm_hash, expected_version)` and then call `finalize_upgrade()`. Finalization verifies the installed executable hash and the running code's version before publishing the upgrade event. If the expected version is wrong, finalization fails and the admin can submit a corrected upgrade. `get_contract_version()` reports the running binary. When upgrading from version 2, use that version's hash-only upgrade interface, then check the installed code hash and running version directly.

For a vault with the legacy position vector, call `migrate_position_index(32)` repeatedly until it returns zero. Each call indexes up to 32 users and records its cursor in the same transaction. Custody balance changes wait for completion. Paged reads continue to include the remaining legacy users. The admin can then call `migrate(3)` on a vault with an earlier schema. Fresh vaults start at schema 3.
